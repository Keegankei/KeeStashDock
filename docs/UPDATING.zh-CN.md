# 更新与恢复

[English](UPDATING.md)

## 检查、下载与重启升级

从 1.2.2 开始，可通过托盘菜单或“设置 > 关于”的“检查更新”按钮获取新版本。软件仅在主动检查时访问官方 GitHub Releases，忽略草稿和预发布版本。

如果 API 达到限额或无法连接，本次检查会继续尝试仓库的 GitHub 官方最新发布链接，只接受重定向到同一仓库的稳定数字版本标签。发现新版后，还会核对预期 SHA-256 文件与压缩包响应头，检查期间不下载 ZIP。通过此方式检查时，可点击“打开发布页面”查看完整更新说明。这使用 GitHub [官方文档中的最新发布链接](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases)，无需访问令牌，也不使用镜像。

一次检查最多等待 30 秒，可随时取消。同一更新窗口内，已验证结果缓存 30 秒，失败后短暂退避，并遵循 API 返回的限额重置或重试时间。失败后可点击“重试”；处于退避期时不会连续发送请求。

查看版本、更新说明、下载大小和安装目录后，点击“下载更新”。下载文件存放在安装目录之外，可在下载期间取消。软件会校验 SHA-256、文件清单、压缩包路径和大小限制，校验通过后才允许“重启并升级”。

如果尚未尝试“重启并升级”，关闭更新窗口或重新检查时，会清理已下载的暂存包。下载失败或取消时也会尝试清理临时目录；文件占用或权限不足可能使临时目录保留，供之后清理。这些操作不会修改已安装的程序。

重启需要单独确认。软件处理未保存编辑、停止已安装的离线翻译服务、保存设置，并备份数据库和其他用户文件。辅助程序等待原进程退出后替换文件，再从原路径启动新版本。受保护目录可能需要 Windows 管理员授权，正常应用仍以原用户身份启动。

网络失败不代表“已是最新版本”。可重试或打开官方发布页，软件不会自动切换到其他镜像。SHA-256 用于识别下载损坏或文件不匹配，不等于发布者签名；当前未签名程序仍可能触发 Windows SmartScreen 提示。

## 保留哪些内容

完整发布包包含 `update-manifest.json`，请保留在程序旁边。清单只管理随包发布的应用文件，不管理 `Data` 或 `%AppData%` 中的用户数据。

整理后的发布包将 .NET 运行时合并在根目录的 `KeeStashDock.exe` 中，使用说明归入 `Docs`，项目和依赖许可证归入 `Licenses`；语言包和可选组件安装目录保持原位；标准包不预装 OCR 或本地翻译引擎与模型。请始终解压完整压缩包。从旧平铺目录通过软件内更新时，只有旧清单登记且内容未改动的旧运行库才会被移除，程序入口和用户数据位置不变。

- 条目、设置、翻译凭据、截图、草稿、日志和备份保留在原位置。
- 已安装的 OCR 原生引擎和模型（包括受支持的旧便携组件），以及离线翻译运行时、模型会保留；随包提供的安装脚本可正常更新。
- 自定义文件会保留。遇到不属于清单的同名文件、被修改的应用文件或不安全的链接路径时，更新会停止，不会静默覆盖。
- 只有旧清单证明属于程序且内容未改动的过时文件才会删除。
- 升级保持安装路径，不改动快捷方式或开机启动注册。

1.2.2 继续使用数据库结构 v4。应用文件回退不会回退数据库；只支持 v1–v3 的旧程序不能打开 v4 数据库。

## 从 1.2.1 首次升级

1.2.1 没有更新按钮或文件归属清单，首次升级需要手动操作：

1. 从[官方发布页](https://github.com/Keegankei/KeeStashDock/releases/latest)下载完整应用 ZIP 和校验文件。
2. 在设置中停止已安装的离线翻译服务，退出应用及托盘进程，备份正在使用的数据目录。“设置 > 关于”显示实际数据路径。
3. 将完整新包解压到新的目录，暂时保留旧程序目录。
4. 原来使用便携数据时，将整个 `Data` 目录复制到新目录。原来使用 `%AppData%` 回退数据时，需要把该数据复制到新可写目录的 `Data`，或继续使用会解析到同一回退位置的不可写安装目录，避免误创建空库。不要覆盖运行中的数据库。
5. `%LocalAppData%\KeeStashDock` 中的组件仍可使用。旧便携目录中的 `OfflineTranslation/runtime` 仅在服务停止后单独复制，不要覆盖新安装脚本。新包不包含旧便携 OCR 引擎与模型；若未复制这些组件，请使用软件内“安装 / 修复”，安装到用户组件目录。组件有问题时也可使用同一操作。
6. 启动新版本，核对条目和设置，并将桌面或任务栏快捷方式更新到新目录。
7. 如果之前开启了**开机启动**，请在新版设置中先关闭再开启该选项。旧启动项可能仍指向旧程序，此操作会登记新的程序路径，避免下次登录 Windows 时启动旧版。确认无误前保留备份和旧目录。

安装 1.2.2 后，后续可优先使用软件内的同路径升级。没有有效清单的目录只提供手动升级指引，更新器不会猜测哪些文件可以删除。

## 替换较早的 1.2.2 候选版

1.2.2 正式包需要手动替换较早的 1.2.2 候选包：各候选版的数字版本也为 1.2.2，“检查更新”不会将正式包视为更高版本。请按上述手动流程操作，迁移目录后也需重新登记开机启动。确认新包正常前，请保留旧目录和数据备份；若 OCR 组件缺失，请使用“安装 / 修复”。1.2.2 准备期间新增的组件保留规则不会改变较早候选版更新器的行为。

## 更新失败与中断恢复

暂存和恢复文件位于 `%LocalAppData%\KeeStashDock\Updates`。事务目录内包含 `transaction.json`、受管理应用文件备份和 `RECOVERY.txt`。用户数据快照保存在当前数据目录下的 `Backups/BeforeUpdate-*`。这些目录可能含私人信息，不要直接上传到公开问题单。

辅助程序在新进程完成启动检查前保留旧程序文件。替换或启动失败时，会尝试安全回退。如果文件占用、权限拒绝、安全软件隔离或外部修改使回退无法完成，恢复文件会继续保留，提示中会给出路径。

更新中断后，重新运行已安装程序，按提示恢复。如果该程序无法启动，可按 `RECOVERY.txt` 中记录的命令运行暂存辅助程序。先关闭其他应用实例。辅助程序会校验备份和记录后再恢复应用文件；不要将恢复目录直接覆盖到 `Data`。

一旦开始尝试重启升级准备，暂存包可能已被辅助程序或恢复事务引用，即使辅助程序启动失败或之后关闭更新窗口，也会保留该包。确认新版本正常前，请保留暂存包及相关恢复目录；它们不会按未使用下载自动清理。

确认新版本正常后，可自行归档或清理旧的已完成事务及对应暂存目录。清理前确认事务状态为 `Committed` 或 `RolledBack`，且没有更新正在执行。继续保留独立的数据备份。
