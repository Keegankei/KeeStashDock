## 一 界面阴影与双显示模式

### 共用的静态层次

按“桌面 → 自定义背景面板 → 条目卡片”组织视觉。面板外侧使用范围较大、透明度较低的柔和投影，卡片采用更轻、更短的阴影。保留背景裁切、现有蒙层透明度、毛玻璃、圆角和自动文字对比度。

阴影与文字内容分层绘制，避免整层文字参与模糊。透明卡片下方不得新增实心黑底，改变用户设定的透明效果。为阴影预留绘制空间，防止裁切；装饰区域不得改变有效的点击和边缘缩放区域。本次不恢复此前删除的“边缘柔光”功能。

### 可切换的显示方式

在“设置 → 外观”增加“面板模式”。切换即时生效并持久保存；旧配置没有该字段时进入经典模式。两种模式提供相同的功能、快捷键、数据和背景选项。

悬浮模式下另提供“固定透视”和“鼠标跟随”选项：固定透视保持稳定的非零倾斜角度，鼠标跟随使靠近鼠标的一侧向后下压。单独保存该选择，旧配置继续使用鼠标跟随。两种悬浮显示均保留卡片的靠近反馈；经典模式禁用该选择，但保留其保存值。

| 操作 | 经典模式 | 悬浮立体模式 |
| --- | --- | --- |
| 静止 | 保留现有布局，使用克制的静态阴影 | 相同的圆角、配色、字体和间距，置于实时透视平面中 |
| 鼠标靠近或在附近移动 | 保留现有展开、收缩行为 | 鼠标跟随在 180 DIP 范围内使靠近的一侧下压；固定透视保持倾斜角度 |
| 靠近或悬停卡片 | 保留现有悬停反馈 | 独立的柔和增亮与边缘抬升；两层错位轮廓和中空投影分离原有卡片表面与面板 |
| 按下与松开 | 保留原有点击操作 | 按住鼠标期间冻结当前面板姿态，使控件保持稳定 |
| 拖动卡片或窗口 | 保留拖出便签和窗口移动 | 拖动期间冻结当前姿态，保留原有跟随鼠标的移动行为 |
| 编辑文字或打开弹出菜单 | 保留原有输入行为 | 冻结当前姿态，直到编辑或弹出交互结束 |
| 移开、取消、隐藏或切换模式 | 不残留效果 | 平滑归位，取消动画并清理状态 |

第三候选版按维护者进一步说明，将现有界面做空间视觉变换。两种模式保留经典界面的圆角、字体、配色和间距。整个面板实时透视倾斜，上限为偏航 10 度、俯仰 7 度、位移 2 DIP，使用有限的 160 毫秒缓动过渡。鼠标按下、原生窗口拖动、文字编辑和弹出菜单交互期间保持当前姿态。自动化几何、渲染和交互检查已通过，候选参数仍待维护者视觉验收。固定、删除等卡片按钮应独立响应，不能误触整张卡片的点击或拖动效果。

收缩至 44 DIP 顶栏、Windows 减少动画或高对比度开启时，使用原有平面显示。键盘、触控操作不依赖悬停。静止时不运行持续渲染动画。缩放、收缩、重启和切换模式后，保存的窗口位置与尺寸保持稳定，不能把透视和阴影边距反复累加到保存的窗口尺寸中。

## 二 截图时直接识别与翻译

保留截图按钮和 Ctrl+Alt+S 入口。框选完成后保留选区，在选区附近、当前屏幕范围内显示操作栏。再次拖动可重新框选；Enter 默认保存，Escape 或右键取消。

| 操作 | 处理和结果 | 数据保存规则 |
| --- | --- | --- |
| 保存截图 | 按现有分组和有效期规则新增图片条目 | 保存原图和缩略图 |
| 提取文字 | 调用本地 OCR，显示可复制的识别文字 | 不自动创建图片或文字条目 |
| 提取并翻译 | 本地 OCR 后交给当前配置的翻译引擎，用现有气泡显示结果 | 不自动创建条目 |
| 取消 | 退出选区并恢复此前应用界面 | 不保存数据 |

OCR 只识别文字，不另建翻译引擎或配置。复用现有翻译服务、目标语言规则和结果气泡。只有用户选择翻译时，识别出的文字才交给配置的提供方；截图本身不发送给翻译节点。离线翻译继续使用本地服务，失败时不自动切换到云端。

识别文字先展示，由用户主动点击复制，再写入剪贴板；使用现有剪贴板写入保护，避免软件自己的复制被历史记录重复收集。翻译失败时保留识别原文，允许复制或重试。保存为条目始终是独立的主动操作。

分别显示“识别中”和“翻译中”，区分未识别到文字、缺少组件、取消和运行失败。缺少 OCR 或离线翻译组件时，提供进入现有软件内安装／修复流程的入口，不要求用户自己运行 PowerShell。除非另行确认和测试，本次不扩大现有 OCR 语言范围。

框选结束后先恢复应用窗口，再异步识别。关闭结果气泡、重新截图、开始新的翻译或退出软件时，取消旧任务；迟到结果不能重新弹出已关闭气泡。临时截图尽可能仅在内存中处理，不留图片文件、日志内容或数据库记录。

屏幕截图保持物理像素坐标，界面布局单独处理 WPF 缩放。覆盖负坐标显示器、混合 DPI、跨屏选区、小选区、屏幕边缘、长按钮文字及从右到左语言布局。

## 三 划词气泡同时提供复制和翻译

在“设置 → 行为 → 划词动作”新增“复制和翻译”选项，保留“仅复制”和“仅翻译”。选择新选项后，划词气泡中同时显示两个独立按钮，由用户选择执行哪一项，不自动连续执行两个动作。

| 模式 | 气泡按钮 | 行为 |
| --- | --- | --- |
| 仅复制 | 复制到文本坞 | 保留现有复制纯文本并收集到文本坞的行为 |
| 仅翻译 | 翻译 | 使用当前配置引擎翻译，并显示现有结果气泡 |
| 复制和翻译 | 复制到文本坞 · 翻译 | 两个按钮并列显示，各自只执行对应操作 |

升级时保留原有划词动作设置。新配置延续当前的默认复制行为，由用户主动开启双按钮模式。划词气泡总开关和现有外观设置独立保留。

两个按钮均不抢占前台焦点，避免点击后原应用的选区失效；在按钮之间移动时保留同一次选区上下文。复制后短暂保留翻译入口，允许继续翻译同一段文字；如需缓存原文，仅保存在当前气泡会话的内存中，选区变化、气泡关闭或软件退出时清除。仅翻译不新增条目，也不自动复制译文；点击翻译前不向提供方发送文字。

现有外部取词可能通过模拟 Ctrl+C 读取原文，应将此过程的剪贴板更新标记为软件自有操作，避免开启剪贴板历史后把翻译误收集为条目，或让主动复制重复入库。选区变化、关闭结果或退出软件时，复用现有翻译取消流程，迟到结果不得重新弹出气泡。

点击气泡外关闭时，将两个按钮都视为气泡内部；鼠标停留在任一按钮上时保持显示。为变宽的气泡重新计算屏幕边缘和不同 DPI 下的位置，补齐多语言标签与无障碍名称，支持从右到左排列，并验证键盘访问不会丢失原选区。软件内部编辑器中的选中文字也应支持两个动作。

## 四 软件内检查更新与原路径覆盖升级

### 更新入口与流程

在应用菜单增加“检查更新”，并在“设置 → 关于／更新”提供同一入口。共用一个更新窗口，避免重复检查和安装。

1.2.2 仅在用户主动点击时通过 HTTPS 查询项目 GitHub Releases。按解析后的版本号比较，排除草稿和预发布版；匹配 Windows x64 正式包及其 SHA-256 文件。界面展示当前版本、新版本、更新说明和可取得的下载大小。明确区分已经最新、网络失败、访问限流、缺少发布附件和不支持的版本，不静默下载或安装。

更新流程的验收基线：

1. 检查更新并展示结果。
2. 用户选择“下载并升级”，查看目标安装目录。
3. 在暂存目录下载，提供进度和取消。
4. 校验 SHA-256、压缩包结构、目标路径及剩余空间，通过前不修改安装目录。
5. 保存未提交的编辑内容，对实际使用的数据创建一致性备份，并准备旧程序文件的回退副本。
6. 用户点击“重启并升级”后，停止占用文件的应用自有组件，正常退出主程序，由安装目录之外的随包辅助程序执行替换。
7. 只替换受管理的程序文件，从原路径启动，显示成功或可恢复的失败结果。

辅助程序由软件启动，用户无需手动运行脚本。检查、下载和暂存阶段允许取消；进入替换阶段后应完成事务或回退，不能中途留下混合版本。

### 数据与文件边界

保持原安装路径。保留实际使用的便携 `Data` 或现有 `%AppData%` 回退目录，包括设置、凭据、数据库、截图、草稿和备份。保留用户自建文件以及已下载的 OCR／离线翻译运行时和模型。随包组件安装脚本正常更新；替换或删除前，先区分软件自带文件与用户后续安装的组件文件。

使用发布文件归属清单管理程序文件。只有上一版本清单证明属于软件的旧文件才允许删除，不能递归清空或无差别覆盖安装目录。解压路径必须位于暂存目录内，拒绝路径穿越、绝对路径、链接／重解析点、重复或冲突条目以及超限解压体积；目标安装目录同样检查实际解析路径和链接风险。

按进程身份等待确切的旧实例退出，不能仅依赖固定延时。文件被占用、磁盘不足、拒绝提权、只读目录、文件被安全软件隔离或替换中断时，都应保护用户数据。仅在安装目录确实需要管理员权限时申请 Windows 提权。

保存可恢复的本地升级事务状态；新版完成约定的启动健康检查前，保留旧程序文件。本次预计不改变数据库 schema v4。如果后续实现确需数据库迁移，必须先补齐数据备份与配套恢复方案，不能只回退旧程序文件。

SHA-256 用于发现下载损坏或文件不匹配，不等同于发布者签名。本次仍不纳入代码签名。更新仅使用固定项目的发布源及预期 GitHub 附件跳转，不静默切换到未经验证的镜像。

### 首次升级与网络失败

1.2.1 尚无更新按钮，因此首次升级到 1.2.2 需要按文档手动下载和升级一次。新增内置流程用于后续版本。通过受控的较新版本测试包验证更新，不为测试发布虚假的公开正式版。

GitHub 无法访问时提供“重试”和“打开发布页”，同时保留手动升级说明。检查失败不能显示为“已经是最新版本”。

| A | 确认现有面板、截图、组件和退出流程，设计更新文件归属与回退规则 | 明确复用服务和数据边界后再进行侵入性改动 |
