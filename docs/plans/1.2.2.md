# KeeStashDock 1.2.2 Update Plan

[Simplified Chinese](1.2.2.zh-CN.md)

Status: revision-3 candidate implemented and locally validated, not released. Requirements recorded on 2026-10-13; the maintainer confirmed the update-check, card tear-out and screenshot fixes on 2026-10-14 and clarified the spatial UI requirement. Spatial visual acceptance remains pending. Baseline: the published 1.2.1 release and subsequent documentation corrections.

The 1.2.2 candidate implements visual depth, an optional animated panel mode, screenshot actions for immediate OCR and translation, a selection bubble with both Copy and Translate buttons, and an in-app update workflow. Existing capture, clipboard, translation, and portable-data behavior must remain compatible. Actual validation results and remaining limitations are recorded in the [candidate acceptance record](../releases/1.2.2.md); maintainer visual and platform acceptance remain pending.

## Confirmed scope

| Area | Required outcome |
| --- | --- |
| Visual depth | Soft shadows separate the desktop, the panel with its custom background, and the cards above it. |
| Panel modes | Users can switch between Classic and Floating depth; Classic remains the default. |
| Interaction feedback | Floating depth preserves the ordinary UI skin and adds whole-panel perspective that follows the nearby pointer. |
| Screenshot actions | After selecting a region, users can save the screenshot, extract text, or extract and translate. |
| Selection bubble | Add a mode that displays Copy and Translate together, while retaining the existing single-action modes. |
| Updates | An in-app Check for updates button leads to a verified, same-directory upgrade that preserves data and installed components. |

The requirements below remain the implementation and release-acceptance baseline. They describe the intended behavior; the acceptance record distinguishes automated coverage from pending visual and platform checks.

## 1. Visual depth and panel modes

### Shared static appearance

Treat the custom background as the panel surface: desktop → background panel → snippet cards. Add a broad, low-opacity outer shadow and smaller card shadows. Retain background cropping, the existing overlay-opacity control, frosted glass, rounded corners, and automatic text contrast.

Render shadows on separate surface silhouettes so the entire text layer does not pass through a blur effect. Translucent cards must not acquire an opaque black backing. Reserve enough drawing space to avoid clipped shadows, and keep decorative pixels from changing the usable resize or click areas. This does not restore the previously removed edge-glow feature.

### Switchable behavior

Add a Panel mode selector under Settings → Appearance. Changes apply immediately and persist. Older settings without the new field load Classic. Both modes provide the same actions, keyboard shortcuts, data, and background options.

| Interaction | Classic | Floating depth |
| --- | --- | --- |
| Idle | Familiar layout with restrained static shadows | The same rounded UI, colors, fonts and spacing, rendered on a live perspective plane |
| Pointer approaches or moves nearby | Existing expand/collapse behavior | The whole panel gently follows the pointer within a 180-DIP proximity region |
| Pointer moves over a card | Existing hover feedback | Whole-panel perspective plus restrained card lift; the original card design remains intact |
| Card press and release | Existing click action | Freeze the panel's current pose during the press so controls remain stable |
| Card or window drag | Existing tear-out and window movement | Freeze the current pose while dragging; retain the existing pointer-driven movement |
| Text editing or an open popup | Existing input behavior | Freeze the current pose until editing or the popup interaction ends |
| Leave, cancel, hide, or switch mode | No residual effects | Smooth return, followed by cancellation and cleanup of animation state |

The third candidate implements the maintainer's clarified reference: spatial transformation of the existing UI. Keep the Classic rounded surfaces, fonts, colors and spacing in both modes. Apply live whole-panel perspective, bounded to 10 degrees of yaw, 7 degrees of pitch and 2 DIPs of positional offset, with finite 160 ms eased transitions. Keep the current pose stable during mouse presses, native window dragging, text editing and popup interaction. Automated geometry, rendering and interaction checks passed; these candidate values still need maintainer visual acceptance. Button actions such as pin and delete must not trigger the card's press or drag action.

Use the original flat presentation while collapsed to the 44-DIP bar, when Windows animations are reduced, and in high contrast. Keep keyboard and touch use fully functional without hover. Avoid a permanent rendering animation while idle. Preserve the saved window dimensions and position across resize, collapse, restart and mode changes; perspective and shadow padding must not accumulate in saved geometry.

## 2. Screenshot actions with immediate OCR

Retain the screenshot button and Ctrl+Alt+S entry points. After the user selects a region, leave the selection visible and show a compact action toolbar near it, within the current monitor. Allow another drag to reselect; Enter saves by default, while Escape or right-click cancels.

| Action | Processing and result | Persistence |
| --- | --- | --- |
| Save screenshot | Create an image entry using the existing group and expiry rules | Store the screenshot and thumbnail as today |
| Extract text | Run local OCR, then show copyable text | Do not create an image or text entry automatically |
| Extract and translate | Run local OCR, then translate its text through the configured provider and show the existing result bubble | Do not create an entry automatically |
| Cancel | Dismiss the selection and restore the previous application view | Store nothing |

OCR only recognizes text. It must not introduce a second translation engine or provider configuration. Use the existing translation service and bubble, including the current target-language behavior. Cloud translation receives recognized text only after the user chooses translation; screenshots are not sent to the translation provider. Offline translation stays on the configured local service, with no automatic cloud fallback.

Recognized text is shown before any clipboard write. Copy is an explicit user action, guarded against accidental recapture by clipboard history. In the translation path, keep the recognized source text available for copying or retry when translation fails. Saving to an entry remains a separate deliberate action.

Show separate recognition and translation progress, an empty-result message, and actionable failure states. Missing OCR or offline components link to the existing in-app installation/repair flow. Users should not need to run PowerShell commands themselves. The currently bundled OCR language scope remains unchanged unless separately approved and tested.

Restore hidden application windows after region selection, then process OCR asynchronously. Dismissal, a new screenshot, a new translation request, or application exit cancels the previous request; a late result must not reopen a dismissed bubble. Temporary screenshots stay in memory where possible and are not retained as files, logs, or database rows.

Keep physical-pixel capture coordinates separate from WPF layout coordinates. Validate negative monitor coordinates, mixed DPI, cross-monitor selections, small regions, screen edges, and long or right-to-left toolbar labels.

## 3. Copy and Translate in the selection bubble

Add a third choice, Copy and translate, under Settings → Behavior → Selection action. Retain Copy only and Translate only. The new choice displays two separate buttons in the same bubble after text is selected; the user chooses which action to perform. It does not execute both actions automatically.

| Mode | Visible actions | Behavior |
| --- | --- | --- |
| Copy only | Copy to KeeStashDock | Preserve the existing plain-text copy and capture-to-dock behavior |
| Translate only | Translate | Translate through the configured provider and show the existing result bubble |
| Copy and translate | Copy to KeeStashDock · Translate | Offer both actions side by side; each button invokes only its own action |

Preserve an existing selection-action preference when upgrading. New settings continue to use the current Copy default; enabling both actions is an explicit choice. Keep the bubble enable/disable switch and current appearance options independent of the action mode.

Keep both buttons non-activating so clicking them does not steal focus or invalidate the source application's selection. Retain the same selection context while moving between the buttons. After copying, briefly keep Translate available for the same text; if text must be cached, keep it only for the current bubble session and clear it when the selection changes, the bubble is dismissed, or the app exits. Translation alone must not save an entry or automatically copy its result. Do not send text to a provider until Translate is chosen.

The existing external-selection reader may use simulated Ctrl+C. Its clipboard update must be identified as application-owned so clipboard history does not turn translation into an unintended capture or duplicate a deliberate Copy action. Reuse the shared translation cancellation flow when the selection changes, the result is dismissed, or the app exits; stale results must not reopen the bubble.

Treat both button areas as part of the bubble for outside-click dismissal, and keep the bubble open while the pointer is over either action. Recalculate placement for the wider layout at screen edges and across DPI scales. Localize labels and accessible names, support right-to-left order, and verify keyboard access without losing the source selection. Both actions must also work with text selected inside the application's editor.

## 4. In-app update checks and same-directory upgrades

### Discovery and user flow

Provide Check for updates in the application menu, with a matching entry in Settings → About/Updates. Use one shared update window and prevent duplicate check or install requests.

Check the project's GitHub Releases over HTTPS only on user request in 1.2.2. Compare parsed versions, ignore drafts and prereleases, and select the Windows x64 portable archive together with its matching SHA-256 file. Show the installed version, available version, release notes, and download size when known. Distinguish no update, network failure, rate limiting, missing assets, and unsupported versions. No background download or silent installation is planned.

The update flow's acceptance baseline is:

1. Check for updates and display the result.
2. Let the user choose Download and upgrade and review the target folder.
3. Download into a staging directory with progress and cancellation.
4. Verify the checksum, archive structure, destination paths, and available space before touching the installation.
5. Save outstanding edits, create a consistent backup of active user data, and prepare an application-file rollback copy.
6. On the user's Restart and upgrade action, stop application-owned components that hold files open, close the application cleanly, and run a bundled helper outside the replacement directory.
7. Replace only managed application files, restart from the same path, and report success or a recoverable failure.

The helper is launched by the application; users do not execute scripts manually. Cancellation is available during discovery, download, and staging. Once replacement starts, complete it or roll it back rather than leaving a partially installed application.

### Data and installation boundaries

Keep the installation location stable. Preserve the active portable `Data` folder or its existing `%AppData%` fallback, including settings, credentials, databases, screenshots, drafts, and backups. Preserve custom user files and downloaded OCR/offline runtime/model assets. Update shipped component setup scripts normally; distinguish shipped files from subsequently installed component files before replacing or deleting anything.

Use a package ownership manifest for managed files. Remove an obsolete application file only when the previous manifest proves it belongs to the application. Do not recursively erase or blindly overwrite the entire installation directory. ZIP entry paths must remain inside staging; reject traversal, absolute paths, links/reparse points, duplicate/conflicting entries, and excessive extraction sizes. Validate the resolved destination and reject unsafe link-based destinations.

Wait for the exact exiting application instance, using process identity rather than an arbitrary delay. Handle file locks, insufficient space, denied elevation, read-only directories, antivirus quarantine, and interrupted replacement without damaging user data. Request Windows elevation only when the installation folder requires it.

Persist enough local transaction state to recover an interrupted replacement. Keep the previous application files until the new version passes a defined startup health check. This release is not expected to change database schema v4. If a migration becomes necessary, add a coordinated data-backup and recovery design before release; replacing old binaries alone is not a safe database rollback.

SHA-256 detects a corrupt or mismatched download; it does not replace publisher signing. Code signing remains outside this release's scope. Only use the project's configured release source and expected GitHub asset redirects; do not silently switch to an unverified mirror.

### First upgrade and network fallback

Version 1.2.1 has no update button, so the first move to 1.2.2 requires the documented manual download and upgrade procedure. The new in-app flow supports subsequent releases. Test it using a controlled newer-version fixture without publishing a fake public release.

If GitHub is unreachable, offer Retry and Open release page. Retain the manual upgrade instructions. Do not claim the installation is up to date when the check failed.

## 5. Implementation sequence

| Stage | Work | Completion gate |
| --- | --- | --- |
| A | Validate the existing panel, capture, component, and shutdown flows; define update ownership and rollback rules | Agree reusable services and data boundaries before invasive changes |
| B | Add static shadows and the persisted mode selector, then optional interaction feedback | Both modes preserve geometry, input, rendering, and accessibility behavior |
| C | Add screenshot action selection, OCR/translation routing, and the dual-action selection bubble | Screenshot OCR stays transient; bubble Copy preserves capture behavior, and Translate does not create an entry |
| D | Implement release discovery and the update dialog, then staged replacement and recovery | Successful same-path upgrade and injected-failure recovery on isolated copies |
| E | Complete localization, documentation, regression testing, packaging, and release acceptance | All release gates below pass or an unresolved limitation is explicitly accepted |

Stages B and C can be developed independently. Do not enable automatic file replacement until the backup, ownership, process-exit, and rollback checks in stage D are implemented and tested.

Likely integration points are `QuickPanelWindow`, shared card surfaces, `StickyNoteWindow`, `AppSettings`, `SettingsWindow`, `ScreenshotCaptureService`, `LocalOcrService`, `SelectionPopupWindow`, `SelectionWatcher`, `TranslationResultWindow`, the application lifecycle, and new dedicated update services/helper. Keep file replacement out of UI event handlers and make network and filesystem operations testable.

## 6. Acceptance criteria

- [ ] New settings and older settings without a mode field default to Classic; an existing mode choice is preserved. Switching is immediate, persistent, and reversible without restart.
- [ ] Shadows are visible and unclipped with light/dark themes, custom backgrounds, opacity changes, and frosted glass; translucent cards retain their configured appearance.
- [ ] Resize handles, title-bar drag, the collapsed bar, screen-edge placement, and persisted visible dimensions remain correct at 100%, 150%, and 200% scale and on mixed-DPI monitors.
- [ ] Approach, hover, press, and tear-out feedback work without duplicate copy, accidental pin/delete, blocked scrolling, moving click targets, or lingering animation after hide/cancel.
- [ ] Both modes retain the same ordinary UI skin. Nearby-pointer perspective stays within its configured bounds, freezes during input/drag/popup interaction, and returns to the flat view for the 44-DIP collapsed bar.
- [ ] Reduced-animation and high-contrast settings produce a usable static fallback; repeated mode changes and idle operation do not accumulate handlers or active animation clocks.
- [ ] Screenshot Save respects group/expiry behavior. Extract and Extract-and-translate do not create database entries or overwrite the clipboard automatically.
- [ ] OCR success, no text, missing components, cancellation, and failure are distinct. Translation uses only the configured provider and keeps recognized text available on failure.
- [ ] Multi-monitor screenshot selection, toolbar placement, reselect, Enter, Escape, and right-click behave correctly, including right-to-left layouts.
- [ ] Copy only, Translate only, and Copy and translate are selectable and persistent. Existing preferences are preserved; the combined mode displays two distinct buttons without automatically invoking both actions.
- [ ] The selection bubble retains the correct text and source focus for either button, including Copy followed by Translate. With clipboard history enabled or disabled, Copy creates no duplicate entry and Translate does not add an entry. No provider request occurs before Translate is chosen. Pointer movement, dismissal, changed selections, cancellation, screen edges, DPI, right-to-left layout, and internal editor selection behave correctly.
- [ ] No-update, newer-version, prerelease, malformed metadata, network/rate-limit failure, missing asset, checksum mismatch, and canceled download cases are tested.
- [ ] Same-path upgrade preserves data, configuration, custom files, and installed components; a managed obsolete file is removed without deleting user files.
- [ ] File locks, denied elevation, insufficient space, helper interruption, and new-version startup failure trigger a safe rollback where possible; otherwise, data and recovery copies remain intact with actionable recovery instructions. External interference such as antivirus quarantine must not be reported as a successful upgrade.
- [ ] Upgrade tests use disposable installation/data copies, including portable and `%AppData%` cases; neither production data nor the published 1.2.1 assets are modified.
- [ ] New UI strings exist in all 20 locales; the English and translated READMEs, help, component guidance, and upgrade instructions agree.
- [ ] Required CI, the existing automated suites, targeted regression tests, package verification, and maintainer visual acceptance pass for the final release commit.

## 7. Release deliverables

Centralized version metadata is now 1.2.2 for candidate builds; 1.2.1 remains the published stable release. Complete acceptance before publishing the following deliverables:

- A completed changelog section and `docs/releases/1.2.2.md` acceptance record with actual results and known limitations.
- Updated usage documentation and screenshots for panel modes, screenshot actions, the dual-action selection bubble, and update flow.
- `KeeStashDock-1.2.2-win-x64.zip` and its `.zip.sha256` file, including any shipped updater/helper manifests and required license notices.
- A protected-branch PR, successful required CI, an annotated release tag, and GitHub Release assets verified after upload.

Do not repack or replace the existing 1.2.1 release. New translation providers, expanded OCR languages, paid signing, a full 3D rendering engine, and unrelated repository cleanup are not part of this plan.
