# KeeStashDock 1.2.2 candidate acceptance record

Candidate revision 3 was implemented and locally validated on **2026-10-14** after maintainer testing and
clarification of the spatial UI requirement. The maintainer confirmed the update
check, card tear-out and screenshot selection fixes in revision 2. The revised
perspective UI still requires maintainer visual acceptance. This is not a
published release. The published 1.2.1 ZIP and checksum are unchanged.

## Implemented scope

- Classic/Floating panel modes, soft outer/card shadows, and the same ordinary
  rounded UI skin in both modes. Revision 3 adds whole-panel perspective following
  the nearby pointer, with projected shadows and stable controls during input.
- Screenshot Save, Extract text, and Extract and translate, with transient OCR,
  explicit copying, component guidance, cancellation and source-text retention.
- Separate Copy/Translate selection-bubble actions, source-session caching,
  clipboard-history suppression and temporary non-activating keyboard shortcuts.
- Explicit GitHub update checks, verified download/staging, same-path managed-file
  replacement, user-data snapshots, process identity checks and health-gated
  rollback/recovery. No silent installation or publisher signing was added.
- Twenty language packs and help text, four READMEs, screenshot/upgrade guidance,
  ownership-manifest tooling and additional CI checks.

## Revision-3 validation status

The revision-3 Release build passed with **0 warnings and 0 errors**. The full
local .NET run passed with **464 tests: 463 passed, 0 failed and 1 skipped**.
The existing symbolic-link privilege-dependent fixture is the only skip.

New coverage verifies live projected button hit testing, text and popup
coordinates, retained control state across mode switches, bounded geometry,
nearby-pointer following, interaction freezing, fixed window dimensions,
rounded hollow shadows and DPI scaling. Rendered color, alpha and text checks
cover direct and nested WPF drawing; an emissive-material alpha defect found
during preview review was fixed before this run. Package verification is recorded
below. Current-head Windows CI results are reported on [PR #9](https://github.com/Keegankei/KeeStashDock/pull/9).

The new Floating presentation keeps the Classic rounded surfaces, fonts, colors
and spacing. It uses live whole-panel perspective within a 180-DIP pointer
proximity region, bounded to 10 degrees of yaw, 7 degrees of pitch and 2 DIPs of
offset, with finite 160 ms easing. Mouse presses, native window dragging, text
editing and popup interaction freeze the current pose. The 44-DIP collapsed bar,
reduced-animation settings and high contrast use the original flat presentation.
Automated checks cover these bounds and transitions. Physical-monitor visual
and interaction acceptance remains separate from the passing fixture results.

## Previous validation and confirmed fixes

The revision-2 Release build passed with **0 warnings and 0 errors**. Its final
local full run had **453 .NET tests: 452 passed, 0 failed and 1 skipped**.
The skipped fixture needs file-symbolic-link creation privileges unavailable to
the validation account; separate PowerShell tests exercised actual NTFS junction
rejection successfully. This run includes the final UI, startup/recovery,
stage-cleanup and concurrent metadata read/write regressions.

The maintainer has confirmed that revision 2 fixes the following three defects:

- GitHub API rate limits now fall back to the official repository's latest
  release page. Checks have one deadline, cancellation, validated-result caching
  and retry backoff. A newer version still needs matching official archive and
  checksum assets; checking does not download the ZIP. The dialog provides
  localized fallback progress, Retry and Open release actions.
- Sticky-note shadows no longer create their HWND during the owner's initial
  `SizeToContent` layout. That re-entrancy collapsed 280-DIP notes to a 1–2-pixel
  sliver. A shown-window regression covers both modes, long/short content,
  moving, repeated settings changes, hide/show and close-before-shadow creation.
- The global selection-bubble dismissal handler now defers during capture,
  so a screenshot overlay's initial left press starts selection instead of
  cancelling its shared operation. Routed-event tests also verify right-click
  cancellation and normal bubble dismissal after capture.

A live read-only check against GitHub completed through the release-page
fallback in about 1.7 seconds and found no stable release newer than 1.2.2.
An immediate repeat used the validated cache. This is one observed network check,
not a guarantee that GitHub is reachable from every network.

All **15 Python offline-helper tests** passed. PowerShell checks passed for
offline process identity, native-runtime setup decisions, cleanup protection,
28 publish-privacy fixtures and update-manifest generation/verification,
including modified/missing/extra files, incorrect versions, invalid ownership
paths, private data and junctions. Initial sandbox-only temporary-file/socket
restrictions were resolved by running the same isolated tests with the required
local access; they were not treated as application defects.

The NuGet advisory check, including transitive desktop dependencies, reported no
known vulnerable packages in its configured feeds on 2026-10-14. This is not an
antivirus scan or a review of every optional native/model asset. The candidate
resolves .NET and Windows Desktop **10.0.13**; upstream runtime notices were
refreshed from that exact NuGet package.

Targeted automated coverage includes:

- Default and persisted panel modes, unchanged visible geometry/44-DIP collapse,
  non-activating click-through shadow ownership, hollow translucent interiors,
  finite motion clocks and hide/close cleanup.
- Screenshot action routing and keyboard behavior, synthetic DPI/negative-coordinate
  crops, transient OCR persistence boundaries, failure/cancellation and explicit

- Selection caching across Copy then Translate, duplicate-action prevention,

- Stable release/version selection, invalid/missing metadata, rate limits/network
  errors, checksum mismatch, cancellation and stalled response-body timeout;

- ZIP traversal, reserved paths, links, conflicting/duplicate/undeclared files,

- Disposable installation apply/rollback/commit, obsolete managed-file cleanup,

Actual WPF controls were rendered using synthetic notes for Classic/Floating

## Remaining acceptance gates

- Successful required Windows CI on the final PR head before merge.
- Maintainer visual/interaction acceptance of whole-panel perspective and shadows with
  actual custom backgrounds, light/dark/high-contrast themes, opacity/frosting,
  card dragging and 100%/150%/200% mixed physical monitors.
- Real screenshot/reselection and OCR workflows on the intended machines,
  external selection focus, non-Latin text, RTL layout and provider credentials.
- A complete real-process upgrade/restart in an isolated Windows session,
  including read-only installation/UAC acceptance and denial, reboot/power loss,
  antivirus interference, startup failure and `%AppData%` fallback. The user's
  normal application was already running on this host; it was not stopped or
  summoned to run a conflicting full application fixture.
- Clean Windows 11 validation and best-effort Windows 10 compatibility. Automated
  fixtures are not certification of every display/GPU/accessibility combination.

The in-app updater begins with 1.2.2. The first upgrade from 1.2.1 is manual;
follow [Updates and recovery](../UPDATING.md) and keep a separate data backup.
